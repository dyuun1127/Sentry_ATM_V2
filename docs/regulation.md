# 규정 엔진

`sentry_atm.regulation` 은 「항공교통관제절차」(국토교통부고시 제2022-534호)와
AIP RKTU 를 코드로 옮긴 계층이다. 원본 PoC 가 `SIMULATION_ASSUMPTION` 으로
라벨링해 두었던 자리에 실제 조항과 전사값을 넣는다.

## 1. 왜 따로 두는가

PoC 는 수평 5NM 을 `ASM-018 PROVISIONAL POC ASSUMPTION` 으로 명시하고 구조를
먼저 세웠다. 값을 몰라서가 아니라, **어디에 무엇이 들어갈지 자리를 먼저 만드는
편이 나중에 실제 값을 넣기 쉽기 때문**이다.

이 계층이 그 자리에 들어간다. 판정 결과에는 언제나 **근거 조항이 붙는다** —
관제사에게 상신할 때 붙일 근거이자, 검증·인증 가능성의 근거다.

**결정론 판정 경로는 외부 의존성이 없다.** 학습(`predict`, `mbe`)과 해석적 확률
(`resolution`)만 numpy·scipy·scikit-learn·torch 를 쓰며, 그 임포트는 전부 함수
안에 있다. 그래서 `pip install -e ".[learning]"` 없이도 규정 판정은 그대로 돈다.

## 2. 무엇이 어디에 있는가

### 판정

| 모듈 | 근거 | 하는 일 |
|---|---|---|
| `rules.py` | 5-5-4, 4-5-1, 2-1-4 | 어떤 상황에 어떤 최저치가 적용되는가. **조항에 붙은 조건까지** 구현한다 |
| `separation.py` | 5-5-4, 4-5-1 | 기존 `SeparationRuleProfile` 자리에 끼워 넣는 어댑터 |
| `policy.py` | — | 체계 전체가 쓰는 **활성 분리 프로파일 한 곳** |
| `conflict.py` | 5-5-4, 4-5-1 | 기하·규정·공역을 묶어 항적 집합 전체를 훑는다 |
| `geometry.py` | — | CPA 해석해와 보호실린더 침범 구간. 순수 기하만 |

`rules.py` 가 조건까지 구현한다는 것이 핵심이다. 표만 옮기면 틀린다 — 예컨대
항적난기류 분리(5-5-4 사)는 후행기가 선행기 비행경로 측방 2,500ft 이내이면서
1,000ft 미만 아래일 때만 적용되고, 착륙 시 최저치(5-5-4 아)는 그와 **별개로
"부가하여"** 적용된다.

### 자원과 흐름

| 모듈 | 근거 | 하는 일 |
|---|---|---|
| `runway.py` | 3-9-6, 3-10-3 | 출발·도착이 같은 활주로를 두고 경합한다 |
| `sequencing.py` | 2-1-4, 4-5-1, 5-5-4 | 착륙 순서, 슬롯 시각, 배정고도 사다리, 중심선 합류 |
| `hold.py` | 4-6-1 ~ 4-6-7 | AIP 공고 장주로 도착 흐름에 시간을 만들어 넣는다 |
| `schedule.py` | — | 민항 운항 시간표. 청주는 활주로 공용 구조상 시간당 7~8 슬롯 |

활주로는 공중 분리와 **근거 조항이 다르다.** 한 번에 한 대만 쓰는 자원이고,
후행기가 얼마나 기다리는가는 선행기가 무엇을 했느냐에 달렸다 — 착륙해서
활주로를 개방했는가(3-9-6 나), 이륙해서 종단을 통과했는가(3-9-6 가 / 3-10-3 가 2).

체공은 **장주를 지어내지 않는다.** RNP RWY 24R 에 IKAPO(7,000ft)와 COWON(6,000ft)
두 곳이 AIP 에 공고되어 있고(AD CHART 2-25), 공고된 장주가 있으면 4-6-1 나 2)에
따라 "AS PUBLISHED" 로 지시할 수 있다. 이 모듈은 그 공고값을 읽어 재현할 뿐이다.

### 공역과 관할

| 모듈 | 근거 | 하는 일 |
|---|---|---|
| `sector.py` | 2-1-15 | 관제기관별 담당 구역 포함 판정 |
| `handoff.py` | 2-1-15 | TWR → GCA → 상위섹터 → ACC 이양 사슬과 그 조건 |
| `route.py` | ENR 5.1 | 복귀 경로를 **관제 지시로 표현 가능한 형태**로 만든다 |
| `mission.py` | ENR 5.2 | 출격에서 복귀까지를 하나의 생애주기로 |

청주 관제는 AIP 를 그대로 읽으면 폴리곤 하나가 아니다.

```
청주 GCA 담당 = T17 회랑 (Class D/E, 1,000ft AGL ~ 6,500ft AMSL)
              ∪ 청주 터미널 Class C (관제권 5NM + 남서·북동 확장 + 5~10NM 링)
              − 성무 Class D (중첩 제외)
```

T17 회랑만 쓰면 RWY 24R 최종접근(TURTU~TU746)이 전부 회랑 밖으로 나온다.
회랑의 남동측 경계가 공항을 스치듯 지나가고 접근로는 그 남동쪽에 있기 때문이다.

**중원 TMA 전체가 전사돼 있다** (ENR 2.1-6, AIRAC AIP AMDT 11/25). 담당은 T17
하나뿐이고 나머지는 인접 기관이지만, 경계가 있어야 어디로 이양되는지 판정할 수
있고 스코프에도 그릴 수 있다.

| 섹터 | 기관 | 고도 | 등급 |
|---|---|---|---|
| **T17** | **CHEONGJU GCA** | 1,000ft AGL ~ 6,500ft AMSL | D, E |
| T17_UPPER | OSAN APP | 6,500ft AMSL ~ FL145 | D, E |
| T18 | JUNGWON APP | 1,000ft AGL ~ FL175 | C, E |
| T19 | JUNGWON APP | 1,000ft AGL ~ FL145 | D, E |
| T20 | JUNGWON APP | 5,500ft AMSL ~ FL145 | D, E |
| T21 | JUNGWON APP | 1,000ft AGL ~ 3,500ft AMSL | C, E |
| T22 | JUNGWON APP | 9,500ft AMSL ~ FL175 | E |

T17_UPPER 는 좌표를 다시 적지 않고 T17 과 같은 도형을 가리킨다 — 두 벌로 두면
언젠가 어긋난다.

경로는 **임의 곡선을 그리지 않는다.** 관제사가 낼 수 있는 것은 "DIRECT (픽스)"
또는 "레이더 유도 침로 XXX" 이므로, 경로는 고시된 픽스를 잇는 직선 구간의
연속이어야 한다. 부드러운 최적 곡선은 계산상 짧아도 지시로 옮길 수 없다.
제한구역은 고도 상한이 있으므로(R19 3,400ft, R152 2,100ft) 고도도 함께 본다.

### 기반

| 모듈 | 하는 일 |
|---|---|
| `data.py` | `reference/*.json` 로더. **어떤 수치도 코드에 하드코딩하지 않는다** |
| `geo.py` | AIP 좌표 파싱, WGS84 거리·방위, 국지 평면 좌표계 |
| `state.py` | 항적 상태 표현과 단위 규약 |
| `bridge.py` | 국지 x/y ↔ 위경도. 규정 엔진과 본체를 잇는다 |
| `sortie.py` | 출격 시나리오 조립 |
| `synth.py` | 합성 항적 생성기 |

### 학습 (선택)

| 모듈 | 하는 일 |
|---|---|
| `predict.py` | 물리 기준선 + 학습 잔차보정. 궤적 전체를 신경망이 생성하지 않는다 |
| `mbe.py` | 무엇을 관제사에게 상신할 것인가 |
| `resolution.py` | 회피 후보와 재검증, 불확실성 하 충돌확률 |

`mbe.py` 만 학습으로 채우는 이유가 있다. 고시 2-1-2 는 *"모든 상황에 통일적으로
적용되는 업무 우선순위의 표준 목록을 설정하는 것은 불가능"* 하며 관제사가 자신의
기량으로 판단해야 한다고 명시한다. 즉 **상신 임계치의 근거가 규정에 없다.**
근거가 있는 것은 규정으로 판정하고, 없는 것만 학습으로 채운다.

## 3. 참조자료

`regulation/reference/` 아래 JSON 네 개다. AIRAC 개정 시 이것만 교체한다.

| 파일 | 내용 |
|---|---|
| `airspace.json` | 관제권·회랑·제한구역·훈련공역 경계와 고도 블록 |
| `procedures.json` | 픽스, 접근·출발 절차, 공고 체공장주 |
| `aircraft.json` | 기종 16종과 후류등급. 회전익 1종은 고정익 시퀀스와 분리 처리 대상이라 기종 목록에서 빠지고 등급만 남으므로, `POC_AIRCRAFT_TYPES` 는 15종이다 |
| `terrain.json` | 지형 (고도값 없음 — `ASM-037` 참조) |

전사값이 맞는지는 `tools/validate_aip.py` 가 검사한다. AIP 가 고시한 거리·방위
67건을 전사 좌표로 재계산해 대조한다. **코드에 박힌 상수가 아니라 전사값을 보는
게이트**다.

```powershell
.\.venv\Scripts\python.exe tools/validate_aip.py
```

## 4. 활성 프로파일

분리 판정의 기본값은 한 곳에서 정한다.

```python
from sentry_atm.regulation.policy import active_separation_profile
```

탐지기·위험평가기·세션 읽기모델이 각자 기본값을 들고 있으면 한 곳만 바꿨을 때
서로 다른 기준으로 판정하게 된다. 실제로 `ConflictRiskEvaluator` 는 사건의
`rule_profile_id` 가 자기 프로파일과 다르면 **거부**하므로, 그 불일치는 조용한
오차가 아니라 즉시 실패로 나타난다.

주입은 그대로 가능하다 — 주입하지 않았을 때의 기본값만 여기서 결정된다.

## 5. 좌표 정확도

세 가지 용도에 각각 다른 도구를 쓴다.

| 용도 | 도구 | 이유 |
|---|---|---|
| AIP 절차 검증 | `vincenty_inverse` | AIP 고시값이 WGS84 측지선이므로 역해로 대조 |
| 국지 항적 계산 | WGS84 곡률반경 평면 | 자오선·묘유선 반경을 따로 씀 |
| 대략 거리 | 대권거리 | 정확도가 필요 없는 곳 |

평균 반지름 구면을 쓰면 36.7°N 에서 축척오차가 0.23% 난다. 곡률반경으로 바꾸면
쌍 거리 오차가 22m 에서 1.9m 로 줄어든다. 실측값은 `tests/unit/regulation/test_geo.py` 에 있다.

## 6. 한계

- 규정 판정은 고시·AIP 전사값을 따르지만 **공식 인증을 받은 관제 판정이 아니다.**
- 민항 시간표는 합성값이다. 출처와 생성 방식은 `docs/assumptions.md` 에 기록돼 있다.
- `terrain.json` 에 고도값이 없어 최저고도 판정 일부가 잠정값이다 (`ASM-037`).
- 학습 산출물(`models/predictor.pt`, `models/mbe.pkl`)은 라이브러리 판에 묶인다.
  언피클이 깨지면 값을 손으로 맞추지 말고 `tools/train_mbe.py` 를 다시 돌린다.

공식 근거가 없는 값은 전부 [`assumptions.md`](assumptions.md)에 있다.
